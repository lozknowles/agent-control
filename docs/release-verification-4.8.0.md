# Agent Control 4.8.0 release verification

Agent Control 4.8.0 is sealed only when the source reconciliation, architecture, neutrality, security, complete test suite, virgin installation, authentic 4.7.1 upgrade, backward compatibility, ordinary-device regression, final-source physical Pixel execution, Mallow routing, token correctness, Estate/Node/Run navigation, human-readable evidence, desktop/mobile visual review, documentation, archive inspection, and checksum gates all pass.

The immutable release receipt and gate record are release assets. They bind the exact public source commit, source archive, test results, installation and upgrade evidence, physical execution, visual evidence, and artifact hashes. A focused test run or an earlier candidate screenshot cannot replace final-source qualification.

The physical demonstration uses a Pixel/Podroid/QEMU/Alpine/SSH/Podman route as evidence for the generic nested-execution architecture. None of those names is a production architectural dependency. Podman is physically qualified on that route; Docker and LXC executable discovery is supported without claiming physical execution qualification.

For the deterministic container run, model token telemetry is not applicable and must not be shown as a measured zero. Existing model-backed accounting continues to distinguish input, cached input, fresh input, and output when provider evidence supplies those values.

Large current screenshots and raw physical evidence remain outside normal source pulls. Public source distribution excludes credentials, private evidence, configuration, state, caches, and runtime output. Publication does not deploy an operational installation.

The release does not qualify AVF/pKVM, a resident guest worker daemon, or physical network-disconnection recovery, and it does not claim autonomous self-extension.
