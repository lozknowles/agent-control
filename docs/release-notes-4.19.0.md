# Agent Control 4.19.0

Agent Control 4.19.0 turns the provider-neutral Computer Use boundary into measurable, limited multi-provider execution infrastructure. It does not add provider lock-in, enable a production route or claim unrestricted desktop autonomy.

## Two physical providers

- Playwright drove Microsoft Edge against disposable unauthenticated loopback tasks.
- Windows Sky drove a fresh unsaved Notepad surface through the existing `WindowsSkyComputerProvider` and the Codex `@oai/sky` Windows adapter.
- Both providers executed the exact frozen CU-MP-001 intent and reached independently verified terminal state through the common Agent Control boundary.
- Windows Sky also physically exercised STEP and MANAGED_RUN for native text entry. Browser-only semantics that were not available on that surface remain `UNSUPPORTED` and are excluded from failure rates.

## Measured outcomes

The retained baseline contains 17 attempts: 14 supported and 3 explicitly unsupported. All 14 supported attempts reported provider completion; 7 independently verified and 7 were false successes by design or unrecovered outcome. The mandatory adversarial subset detected all 4/4 false-success cases. Provider completion never overrode independent verification.

The focused Computer Use regression passed 69/69, including the existing CU01-CU08 boundary, Windows Sky lifecycle protections, bridge contract coverage and the new benchmark/history/routing tests.

Three no-recovery trials verified 0/3. The same deterministic transient task under governed recovery verified 3/3, with one retry each. This is evidence for the frozen recovery case, not a general open-world reliability claim.

Fixed-provider and verified-history routing both verified the shared task once. The history-aware policy selected Windows Sky after capability, locality, budget, verification support and task-class history gates. One shared task does not establish a general routing advantage or provider ranking.

## Budget, privacy and economics

The zero-provider-charge ceiling rejected a paid candidate before execution, while a free but incompatible candidate was rejected on capability. The `LOCAL_ONLY`/no-external-processing policy rejected the external candidate with zero operational calls.

Observed provider charge was zero. Cost per provider completion and per verified success were therefore zero for provider/API charge only. Local compute monetary cost and energy remain unavailable because no authoritative conversion or per-run energy measurement exists. Hardware time remains separate and retained per attempt.

## Boundaries

Coasty remains `PROVIDER_ACCESS_UNAVAILABLE`; no adapter, call, cost or performance claim was fabricated. OSWorld remains `DEFERRED_FOR_FULL_QUALIFICATION`; the release includes a concrete official-methodology qualification plan, not a score. No production service or configuration changed.
