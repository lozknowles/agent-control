# Lazy context, delta and result projection

The physically eligible opt-in path removes only an exact duplicate of the dispatcher-supplied tool catalogue. It retains task instructions, allowed paths, acceptance criteria, policy text, repository context and verification requirements. Original sources remain in durable evidence.

| Class | Treatment |
|---|---|
| MODEL_REQUIRED | Task, acceptance, allowed paths, current schemas, needed file/test context |
| MODEL_ON_DEMAND | Tested vault primitive accepts only pre-authorised source IDs and rechecks live authority |
| RUNTIME_ONLY | Policy evaluation, leases, ownership, risk checks, budgets, independent acceptance |
| EVIDENCE_ONLY | Full original sources, raw outputs, hashes and projection records |

The on-demand vault is not exposed as a new production tool or endpoint. This avoids granting a context-expansion capability merely because a model asks for it. A future adapter must bind retrieval to ordinary governed tools.

Delta prototype: an identical raw tool result may be replaced by a backward reference only while its original full content remains in the same conversation. A changed result is supplied in full. The cache is per execution and hashes full raw JSON. No history eviction is implemented. Oversized baseline-bounded results cannot obtain a reference to an unseen full result.

Each opt-in result records raw output, SHA-256, raw/model bytes and transformation before projection. No generative summarisation or lossy test-log pruning is enabled. General result compression has NO_MEASURED_BENEFIT in this parcel; exact delta and lazy context remain NEEDS_MORE_QUALIFICATION.

Motivations: lazy exposure COMBINATION; exact delta NEW_AC_TECHNIQUE. Proposed separation: authoritative governance plane -> narrow model interface -> model; the full governing state is not the model context.
