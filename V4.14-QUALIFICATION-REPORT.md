## Observed tests and physical evidence

An initial full repository check on the integrated runtime passed **2,259/2,259** tests with zero failures or skips, plus typecheck, distribution, dashboard/bootstrap syntax, neutrality and limitations checks. A new red regression then demonstrated that exact replacement accepted a copied numbered read-display; the guard was extended before mutation and its 10 focused mutation-workspace tests passed. Sixteen identity tests and 27 Factory tests passed after the twelve-colour refinement. The first full check on the versioned committed candidate failed because its manifest exposed a local worktree path; that path was removed and the three neutrality tests passed. A later full run passed 2,259 tests and failed one pre-existing model-server test when two sequentially requested ephemeral ports collided. The focused test then passed. Its port selection was made distinct in a test-only commit. A final full check against the corrected candidate is required; the failed runs remain retained evidence.

A disposable local Factory demonstration ran three concurrent read/model/test Jobs using Gemma 4 E2B Q8 (`e049411c01fb7a81161768c52e38828970e55a64e22738957adcbe51d20f1c8e`). All three Jobs succeeded and had **14,229 ms** of common overlap. The final twelve-slot palette mapped the observed Runs to distinct slots 8, 3 and 5. The live browser recorder was armed before execution. The converted MP4 is 1600×900, 18.133 seconds, SHA-256 `78ffb01d142b3cb245c942f47597601748fde6b51b252158962c1fbe3b9d1e54`; full decode, final-frame inspection and remote/local hash equality passed. This bounded clip precedes final candidate metadata freeze and does not show semantic tools or no-progress recovery.

The previous NO_PROGRESS_V1 research corpus had 18 cases: 5/5 loop detections, zero missed loops and zero false positives among 13 negative cases, most synthetic. Its benchmark-native HR control remained 0/5 and terminated after repeated requests. Candidate physical no-progress recovery has not been demonstrated. The previous 264 semantic diagnostic reconciliations belong to the separate semantic-tool research run and are not combined with v4.13's 47-case evaluation or presented as new v4.14 results.

Two existing local 3B models received the same synthetic native-function format probe. Qwen2.5-3B-Instruct returned the expected function call at 128 and 512 output-token limits. Qwen2.5-Coder-3B returned no function call and ended at the output-token limit at both 128 and 512; this is a budget-limited format result, not proof of model incapability. No tool was dispatched, no Job was admitted, and no semantic-tool success is claimed. Qwen3.8-27B was not started because the shared GPU was already substantially occupied.

Two `git archive | gzip -n` source packages from the same candidate commit matched byte for byte. An extracted package completed `npm ci`, TypeScript typecheck and one disposable read-only governed Job with a `PASS_SAFE_NON_PRODUCTION` receipt. The maintainer distribution-policy command requires `.git` and therefore cannot run inside the exported archive; it passes in the source worktree. This is a bounded clean-install smoke, not startup, video, uninstall or full installation qualification. A separate disposable ledger test wrote one successful Job under released v4.13.0, read it unchanged under the candidate, wrote a second successful candidate Job, and read both under v4.13.0. The initial helper run created its Job but reported a false failure because it filtered on the versioned Job ID; the filter was corrected and all four subsequent read/create/rollback receipts passed. This proves only the exercised ledger format. Configuration, workers, permissions, diagnostics and new event types still need a genuine upgrade/rollback test.

## Security

The native audit was run on the clean integration source. Its bubblewrap continuation passed all 13 recorded containment controls and used a separate verifier identity. It nevertheless ended with all 12 coverage units PARTIAL, 0 confirmed, 98 `needs_validation` and 79 rejected findings. Nineteen unresolved findings refer to changed files; two refer to changed lines. A targeted real-browser injection check of those two output-encoding paths passed for one hostile markup payload. This does not close the remaining findings. See [security review](SECURITY-4.14.md).
